# 自動コパイロット（伴走モード）— 構想・未着手

**ステータス: 設計の骨格だけ固定してある。実装は1行も無い。**
着手するときはこの文書が出発点で、最初の一歩は実装ではなく計測（§7）。

---

## 1. なにを目指すか

コンパニオン（別デバイスで見る）は、PCと同じ「聞かれたら答える」では体験が
成立しない。PCでは自分が操作の主体で、分からない所だけ指して聞く。タブレットを
横に置いた人は**作業をしながら横目で見ている** — そこに置かれた相棒は、
もっと自律的に動くべきである。

例（Google Analytics で「国別のアクセス解析がしたい」）:

1. 目的を一度だけ言う
2. 「テクノロジーを押してください」→ ユーザーがPCで押す
3. **画面が変わったことを検知して**「次はユーザー環境の詳細を押してください」
4. 表が出たら、該当箇所にハイライトを打ち、
   「モバイルが多いですが、意外とPCも標準より多いですね」まで言う

一歩ごとにユーザーが質問し直すのはコスパが悪すぎて誰もやらない。
**再帰的に説明を深めるプロセスの自動化**が、既存ツールにないAIらしさの本体。
究極形は「つけっぱなしのタブレットが、作業を説明し、フィードバックし、
ミスの予兆に『ちょっと待った』と言う」。

PC版にも同じものが要るが、**コンパニオンから始める**（§6の自己トリガー問題）。

## 2. 3つの直交する軸（混ぜない）

| 軸 | 問い | 実現される次元 | 状態 |
|---|---|---|---|
| **介入のタイミング**（モード） | いつ喋るか | トリガー方針。**スタンダード**＝聞かれたら答える（現行）／**プロアクティブ**＝settleごとに動く。ON/OFFスイッチ・予算・課金はこの軸に付く | この文書の主題 |
| **介入の姿勢**（スタンス） | どう見るか | メンター（引っ張る）／慎重派（ミス・危険の予兆を執拗に見る）／発散・クリエイティブ。エンタメのキャラではなく**介入スタイル**の選択 | **後回し。** スタンダードな機能が満ちてから、Skill/プロンプト注入として |
| **知識**（Skill） | 何を知っているか | 業種・職種の知識（金融・会計・デザイン・エンジニア…）。**新規の仕組みではなく既存のSkill機構の次元**（下記） | 機構は存在。web版の検出に既知課題 |

モードは「呼び出しの回数と契機」、姿勢と知識は「呼び出しの中身」。
予算の話をするときはモードの話だけをし、口調や専門性の話を混ぜない。

**知識の軸はB2Bの導入形態と直結する。** Gateway契約には既に `result.skill`
（注入した知識を応答に明示する）と `input.context` によるSkill判定があり、
「注入している知識は必ずUIに表示する」という家族規則も敷かれている。web版は
detect が `host`/`bundle_id` 依存で発火しないという既知課題（README「未解決」）が
あるが、**B2Bは「この会社は会計事務所」という静的な事実**なので、画面からの
検出に頼らず**テナント設定で常時注入**できる — 検出より簡単な側から始められる。

## 3. トリガー: 時計ではなく settle

「10秒に1回」は二重に損 — 動いていない10秒は無駄撃ち、動いた直後の9秒は沈黙。
「動いたら即」はスクロール中に連射する。欲しいのは**人の操作が終わった瞬間**で、
画素で見ると「**大きな変化 → 短い静止**」（settle）という形をしている。
プルダウンが開く・ページ遷移・ダイアログ、すべてこの形。

検出器は実質もうある。[lib/recent-screens.ts](../lib/recent-screens.ts) の
16×16 RGB署名と `difference()` は毎秒走っても費用ゼロで、閾値は実測済み:

| 実測値 | 意味 |
|---|---|
| 0.000 | 静止した画面 |
| 0.024 | メニューが1つ開いた |
| 0.069 | 50pxスクロール |
| 0.12 (`SAME_SCREEN`) | 「同じ画面」の境界 |
| 0.227 | 別アプリ |

```
Tier 0（毎秒・費用ゼロ）    署名と差分。ノイズマスク更新
Tier 1（イベント・費用ゼロ） settle検出 ＋ 予算制御
Tier 2（LLM・ここだけ有料）  §4の2種類の呼び出し
```

- **ノイズマスク**: 常時動いているマス（動画・時計）は
  [lib/self-share.ts](../lib/self-share.ts) と同じマス目単位の見方で特定し、
  トリガー計算から除外する。「動画が流れているだけで連射」を構造的に防ぐ
- **予算制御**: 最短間隔・時間あたり上限・**無視されたら退く**
  （コンパニオンはバブルが読まれた/タップされたかを知っている。
  連続で無反応なら間隔を倍にする）

## 4. 呼び出しは2種類（性質が違う）

### (a) 目的駆動の誘導 — 常時ONでよい

目的（一度だけ宣言）＋直前の案内＋新しい画面 → 「期待どおり進んだか。次の一歩」。

- **Gateway契約は対応済み**: `input.guidance` —「Copilot進捗時の目的と直前案内。
  `question`とは排他」（`../api-gateway/docs/api-contract.md`）。Mac版のために
  線路が敷設済みで、**契約変更なしで送れる**
- 呼び出し回数は**タスクの手順数で自然に有界**。1回1回が明示的な目的に直結する
  ので価値/費用比が最も高い
- SSEストリーミング（契約済み）で第一声を速く。**プルダウンは儚い** —
  ホバーが外れると消えるので、誘導中は settle 閾値を軽くする
  （0.024＝メニュー開でも発火）

### (b) 目的なしの伴走 — 予算と退き方が本体

「これは厳しい返信ですね。こう返した方が…」のようなプロアクティブな一言。

- 大きな settle（画面種別が変わる 0.12 以上）だけで発火
- **「言うことがなければ黙る」をモデルに許可する**（応答に skip を持たせる。
  内部では結果に到達しているので「無音で終わらない」規則と矛盾しない —
  UIが静かなだけ）
- 安いモデルを「言う価値があるか」のゲートに置く案は、**§7の計測の後で**判断する

## 5. 家族ルールとの整合

- **「ユーザーの明示操作が回答スコープを決める」**: 目的の宣言・モードONが
  明示操作で、再帰的な後続はそのスコープの内側（初回説明で「共有開始も明示操作」
  と拡張したのと同じ形）
- **「注入している知識は必ずUIに表示」**: モードの状態は常時表示する。
  ライブ／ガイドの対名乗りに並ぶ第三の名乗り。見えない自動動作は疑えない
- 見張るのは**PC側**（ストリームと署名機構を持つ）。コンパニオンは表示装置の
  まま、結果は既存の room/peer 経路で流す（ハイライト座標は既に流れている）

## 6. 落とし穴（先に書いておく）

1. **自己トリガーのループ。** ソロ（同一画面）でやると、自分のバブル更新が
   画面変化として検知され、自分に反応し続ける。合わせ鏡問題の親戚で、対策も
   同系（自分の描画領域のマス除外）。**コンパニオン先行の理由はこれ** —
   表示が別デバイスにあるので共有画面に映らない
2. **プルダウンは消える**（§4a）
3. **検証はLLMなしで書ける。** 合成ハーネス（`scripts/check-solo-buffer.mjs`）の
   `__paint` 連続で「操作→静止」を再現すれば、settle検出と予算制御は全部通せる

## 7. 着手順

1. **実装より先に計測。** settle検出を `?debug` の計器として足し、実作業1時間で
   何回発火するかを数える。**その回数×モデル単価がこの機能の原価**で、
   (b)の要否・ゲートモデルの要否は数字が決める
2. (a) 目的駆動の誘導を先行（有界・高価値・契約済み）
3. (b) は計測の数字を見てから
4. 姿勢（スタンス）と知識（業務Skill）の注入はスタンダード完成後、
   Skillの次元で設計する
